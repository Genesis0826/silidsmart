# Enterprise Architecture Frameworks

## Description
Provides the enterprise architecture framing used when reviewing the solution at the business, application, data, and technology levels. These frameworks are not required for every task; they become useful when the team needs to explain how the system supports core capabilities and how changes move across layers. They ensure the solution is designed with clear domain goals, application boundaries, and resilient data structures.

## Workflow
1. Map the business capability or domain concern first.
2. Review the application, data, and technology layers that support it.
3. Identify gaps, duplication, and dependency risks.
4. Produce the architecture artifact that is useful for the decision at hand.
5. Record the transition path if the current state needs to evolve.
6. Keep the artifact clear, concise, and defensible.

## Rules
- Use Zachman, TOGAF, or ArchiMate concepts only when they improve clarity.
- Review business, application, data, and technology layers together.
- Keep deliverables grounded in the actual repo and project scope.
- Avoid making the architecture more complex than the problem requires.
- Document target-state and transition-state views when needed.
- Use the framework to clarify decisions, not to slow them down.
- Keep the architectural viewpoint aligned with actual project implementation.

## Deliverables
- Capability maps
- Process maps
- System context diagrams
- Data flow diagrams
- Layer review notes
